# 발행 (자동)

**시작 전 관문: `.claude/skills/지침/SKILL.md` 를 읽고 `지침확인: 한 줄` 을 적은 뒤 진행한다. 이 줄 없이 한 작업은 무효 (지침 5절).**

## 흐름

1. 최종확인 화면에서 **발행** 버튼 → `작업파일/확인서버.py`가 처리
2. 크롬으로 카드를 1080x1350 PNG로 촬영 (3회 시도)
3. PNG → JPEG 변환 (인스타 API는 JPEG만 받음) → base64로 묶어 `작업파일/webhook.txt`의 Make 웹훅 주소로 전송
4. Make 시나리오 `instagram_publish`: 웹훅 → Iterator → 구글 드라이브 업로드(`insta_cards` 폴더) → 공유 링크 → Array aggregator → Instagram 캐러셀 게시
5. 전송 성공 시 `발행대장.txt`에 한 줄. 실패 시 `오류기록.txt`에 한 줄 적고 멈춤 (PNG는 폴더에 남음)

보내는 JSON 모양 (Make 쪽 필드명과 맞춰져 있음. 바꾸면 양쪽 다 바꿔야 함):
`{"caption": 캡션.txt 전체, "count": 장수, "images": [{"name": "카드01.jpg", "data": base64}, ...]}`

## 폰으로 발행 버튼 누르기

PC를 켜두고 `전체확인열기.bat`를 실행해 두면, 같은 와이파이의 폰 브라우저에서 검은 창에 찍힌 주소(`http://192.168.x.x:8765/`)로 같은 화면이 열린다. 사진 촬영·전송은 PC가 하므로 PC가 꺼져 있으면 안 된다. 처음 한 번 윈도우 방화벽 창이 뜨면 "액세스 허용".

## 확인할 것

- 인스타에 게시가 안 보이면 Make 시나리오 히스토리에서 어느 모듈이 빨간지 본다
- 카드 한 세트 용량은 약 0.5MB. 4.5MB 넘으면 서버가 전송을 막는다 (카드 10장 이상이면 확인)
- Make 무료 한도 월 1,000 작업. 실측: 4장 세트 = 12 작업 (장당 3 + 기본). 7장이면 약 21 작업. 한 번 도는 데 약 1분

## 아직 남은 것

- Make 시나리오의 "Every 15 minutes" 스케줄은 웹훅엔 의미 없음. 첫 발행 성공 후 정리
