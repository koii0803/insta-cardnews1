# 발행 (전자동 — 사람 검수 없음, 2026-09-16 사용자 지시)

**시작 전 관문: `.claude/skills/지침/SKILL.md` 를 읽고 `지침확인: 한 줄` 을 적은 뒤 진행한다. 이 줄 없이 한 작업은 무효 (지침 5절).**

## 흐름

1. 캡션작성이 끝난 폴더마다 실행: `python 작업파일/자동예약.py <제작폴더명>`
2. 자동예약.py가 시각을 뽑는다 — 06:00~08:30 / 15:00~18:00 두 창, 창마다 하루 2건(하루 최대 4건), 같은 날 40분 이상 간격, 창 안 분 단위 랜덤. 자리 없으면 다음 날로 넘어간다(최대 2주)
3. 이어서 확인서버.py의 깃허브예약등록이 돈다: 크롬 PNG 촬영 → JPEG 변환 → **Cloudflare R2 업로드**(`insta-cards/폴더명/` 접두어, babcheck-img 버킷) → 깃허브예약.json에 한 건(시각·캡션·이미지 주소 전부 포함) → 깃허브 푸시. **이미지는 깃허브에 넣지 않는다**
4. 깃허브 액션(`.github/workflows/publish.yml`)이 발행 창에는 15분마다, 그 외엔 매시 정각에 깨서 시간 지난 건을 발행한다: R2에서 이미지 받아 base64 → Make 웹훅 전송. PC 꺼져 있어도 돈다
5. Make 시나리오 `instagram_publish`: 웹훅 → Iterator → 구글 드라이브 업로드 → 공유 링크 → Array aggregator → Instagram 캐러셀 게시
6. 성공 시 발행대장.txt에 `(깃허브예약)` 한 줄, 실패 시 오류기록.txt 한 줄 (액션이 커밋 — PC에서 보려면 확인서버 현황판 또는 `git pull`)
7. 발행(성공·실패 무관) **24시간 뒤** 액션이 R2 이미지를 지운다 (삭제예약.json)

보내는 JSON 모양 (Make 쪽 필드명과 맞춰져 있음. 바꾸면 양쪽 다 바꿔야 함):
`{"caption": 캡션, "count": 장수, "images": [{"name": "카드01.jpg", "data": base64}, ...]}`

## 확인할 것

- 인스타에 게시가 안 보이면: 저장소 Actions 탭에서 scheduled-publish 초록인지 → Make 시나리오 히스토리에서 어느 모듈이 빨간지
- 액션이 정각에 안 돌 수 있다 (깃허브 cron 지연, 수십 분까지 정상). 급하면 Actions 탭 Run workflow
- 카드 한 세트 약 0.5MB, 4.5MB 넘으면 전송 막힘 (카드 10장 이상이면 확인)
- Make 무료 한도 월 1,000 작업. 4장 세트 = 12 작업. 하루 4세트면 월 약 1,440 — **한도 초과**. 하루 2세트(월 720)까지가 무료 안전선, 4세트를 매일 돌리려면 Make 유료 필요
- R2 무료: 저장 10GB — 세트당 0.5MB에 24시간 뒤 삭제라 늘 거의 비어 있다
